# 8 人桌德州扑克开池范围表

按位置展示 8 人桌（UTG → BB）的开池与防守范围：每个位置该玩哪些牌、该加注还是跟注、
以及每手牌的真实胜率。胜率由蒙特卡洛模拟逐手算出，不是估算。

**在线地址：https://julian-cloud-max.github.io/poker-ranges/**

## 页面内容

- **八个位置**横向排列，按真实行动顺序，卡片上直接显示该位置的开池宽度
  （UTG 12.8% 逐级放宽到 BTN 43.3%）。
- **13×13 起手牌矩阵**，两种配色：「按动作」红=加注/3-Bet、绿=跟注、灰=弃牌；
  「按胜率」按色阶显示强弱。每格都印着该手牌的胜率数字。
- **场景切换**：开池（RFI）与面对开池。位置逻辑正确 —— UTG 前面不可能有人开池，
  「面对开池」对其禁用；BB 没有开池决策，默认落在「面对开池」。
  每个位置只列出真正在它之前行动过的玩家作为潜在开池者。
- **手牌详情**：点击任意格查看单挑胜率、8 人底池胜率、对该开池范围的胜率、
  169 手牌中的排名，以及针对当前动作的解释。
- **深链接**：支持 `#BTN/vs/LP/A5s` 这样的地址，可直接分享到某个具体状态。

## 数据是怎么来的

全部由 `build/build_data.py` 算出，用 [eval7](https://pypi.org/project/eval7/)
做蒙特卡洛模拟：

| 指标 | 含义 | 模拟次数 |
| --- | --- | --- |
| 单挑胜率 | 对 1 个随机手牌的摊牌胜率 | 120,000 / 手牌 |
| 8 人底池胜率 | 对 7 个随机手牌能分到的底池份额（8 人公平份额为 12.5%） | 50,000 / 手牌 |
| 对开池范围胜率 | 对手按该位置范围开池时的摊牌胜率 | 50,000 / 手牌/场景 |

`build/eq_cache.json` 缓存单挑与多人底池结果，重跑时只补算缺失项。

**交叉验证**：用完全独立的 [treys](https://pypi.org/project/treys/) 评估器重算，
同种子下两个引擎逐手结果差异为 0.00，抽样最大偏差 0.48 个百分点（在噪声范围内）。

**范围本身是基准线（baseline），不是 solver 精确解。** 未考虑对手倾向、不同筹码深度和 ICM。

## 本地开发

构建产物是 `docs/index.html` 单一文件，CSS、数据、交互全部内联，**无任何外部依赖**，
断网可直接双击打开。

```bash
# 重新生成数据（约 6 分钟，20 核并行）
python build/build_data.py

# 重新组装页面（会自动跑 Tailwind）
python build/assemble.py

# 浏览器端测试：169 格唯一性、场景逻辑、胜率一致性、深链接、移动端溢出、meta 标签
node build/test.js

# 重新生成 1200×630 分享预览图
node build/make_og.js
```

依赖：`python` + `eval7`；构建脚本用 `npx tailwindcss@3.4.17`；测试与配图用 puppeteer。

## 目录结构

```
docs/                  # 部署目录（GitHub Pages 发布源）
  index.html           # 构建产物，单文件
  og.png               # 1200×630 社交分享预览图
build/
  build_data.py        # 范围定义 + 蒙特卡洛模拟 → data.json
  template.html        # 页面模板
  assemble.py          # 拼装成 docs/index.html
  make_og.js           # 生成 og.png
  test.js              # 浏览器端测试
  data.json            # 生成数据
  eq_cache.json        # 胜率缓存
```

GitHub Pages，从 `main` 分支的 `/docs` 目录发布。推送到 `main` 后自动更新。
